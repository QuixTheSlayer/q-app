## Event widgets in imported pages and the AI prompt (`794192d98`)

**What they are:** event widgets are tokens the published page fills in from the event:
- Submit Entry / Register buttons: href `{{event_submit_entry_url}}` / `{{event_register_url}}`, resolved by the Button renderer through `eventRouteMap`.
- End date / end hour / time zone: `{{event_date}}`, `{{event_hour}}`, `{{event_timezone}}`, `{{event_timezone_offset}}` in text, filled by the Text renderer.

**Import:** the importer already kept all of them; a test now locks that in (`promptRules.test.ts`).

**Fix:** the Text renderer replaced only the first occurrence of each token in a text block; it now replaces every one.

**AI prompt** (`importHtmlPrompt.ts`):
- A new "Event widgets" rules section. Submit and Register buttons use the token hrefs exactly, and the deadline is always written with the tokens, never as a fixed date.
- A countdown reads its target from a hidden `#countdown-target` text built from the tokens, and stays hidden unless that parses as a future date.
- Entry and registration forms are not built in the page (they're the event's own); other forms are still allowed.
- All 5 presets use the event widgets. The pitch, hackathon and writing presets have a CTA section instead of their own entry form.
- The list rule is corrected: every list item becomes its own block.
- The commit also carries the user's preset picker (`ImportHtmlAiPrompt.tsx`) and its labels in all 14 `insert.json` locales, which the prompt file depends on.

**Known:** Preview has no event, so tokens show as `{{…}}` there and the countdown stays hidden. The local `db.json` only has sample deadline values, so whether the real date/hour/offset combine into a valid date is still to check on a real event.
