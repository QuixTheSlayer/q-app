## Layers panel: expand accordion/tab/testimonialSlider, add icons, reflect multi-select

**What:** `Layers.tsx` only ever expanded `NODE_TYPE.Container` nodes (root/section/block) — `accordion`, `testimonialSlider`, and `tab` nodes are `type: "content"` but do have real, addressable children per the app's own `isAllowedToInsert`/`getNode` logic, so their children were completely invisible in the tree despite being fully editable on canvas. Added a `getTreeChildren()` helper mirroring that logic (a `tab` node only shows its *currently active* tab, since that's all `getNode` can address by path).

Also added a distinct icon per content type (exhaustive `Record<ContentType, LucideIcon>`, 42 types, TS-enforced), made rows reflect `canvas.isNodeSelected` (multi-selection) not just the single focused node, wired shift/ctrl/cmd-click on a row to multi-select (mirroring `RenderNode.tsx`'s canvas behavior), and switched indentation from tiny compounding margins to explicit per-depth padding plus a vertical guide line.

**Verified live** via Playwright against two real sample pages (id 11 for a plain tree, id 12 for accordion/tab/testimonialSlider) — confirmed the previously-invisible nested content now renders with correct icons.

## Sub Templates panel: fix a filter that silently hid every template

**What:** `MyComponent.tsx` had `if (!component?.plan_type) return` — filtering on an unrelated metadata field as a stand-in for "is this record complete," which silently dropped every template lacking it (including all of dev's mock seed data) with no feedback, and since the array itself stayed non-empty the real "no templates" empty state never rendered either — just a blank bordered box. Replaced it with a completeness check (`thumbnail_url` present), added a loading state, a broken-thumbnail fallback icon, an untitled-template fallback, an accessible delete button, and reworded the placeholder-quality `"EMPTY!"` copy — plus the new `loading`/`untitled`/`delete` i18n keys across all 14 locales.

**Verified live**: seeded a realistic template into `db.json` temporarily, confirmed it renders correctly, restored `db.json`, confirmed the proper empty-state message shows in its place.

## event-page-image-upload: ported image-editor fine-tunes from the builder

**What:** User pointed out this standalone app (embedded via vanilla data-attributes into a host Blade page) has its own, older image upload/crop/edit implementation that never received the refinements already made in landing-page-builder's version. Found and fixed a pre-existing broken build along the way — `ImageEditor.tsx` had two conflicting `Stage` imports (`react-konva`'s component and an unused `konva/lib/Stage` type import), which made Vite/Rolldown fail to bundle the app entirely.

Ported: the 10MB file-size guard the UI already advertised but never enforced; original-file tracking and a "Save Original" upload path alongside the cropped edit (wired into this app's existing DOM-based host-page integration, not the builder's React-context one); corrected crop-rectangle centering and zoom/pan geometry (was offset top-left instead of centered) while keeping this app's own light theme and native `<input>`-based resize panel; a debug-log cleanup and a defensive filename fallback.

**Verified live** via Playwright against a temporary local test harness (this app's own `index.html`/`App.tsx` had no working mount point or visible trigger UI to test against — patched `index.html` temporarily, tested, then restored it exactly): upload, centered crop box, zoom in/out, and dragging the crop rect all confirmed working.

**Left alone, flagged:** a hardcoded `subFolder: '233250'` in `DropZone.tsx` — no visible source for the real event/page id in this repo. (Same day, separately: the actual dev — not this session — wired this up for real via a new `ModalContext` `subFolder`/`updateSubFolder`, read from a `data-subFolder` attribute in `App.tsx`'s click handler.)

## Lock aspect ratio: dead checkbox in one app, missing entirely in the other

**What:** Neither app's resize panel actually preserved aspect ratio. In event-page-image-upload the "Lock aspect ratio" checkbox was hardcoded `checked` with no state or `onChange` — pure dead UI. In landing-page-builder the control didn't exist at all. Added a real `lockAspectRatio` state (default on) to both, so width changes recompute height from the current ratio (and vice versa) when locked.

**Verified live**: with lock on, setting width to 500 correctly resized height from 32 to 444 (preserving a 36:32 source ratio); with lock off, height stayed unchanged on a further width change. Confirmed in both apps.

## event-page-image-upload: real toast severity types

**What:** The single `#toast` element only ever had one green "success" look, with show/hide logic duplicated inconsistently across three files and no shared timer (a second toast fired before the first's hide could get cut short). Added `src/utils/toast.ts` (`showToast(message, type, duration?)`) centralizing the icon swap, color class, and hide-timer, force-restarting the CSS fly-in animation on each call. Added `.toast.warning`/`.toast.error` CSS variants.

**Found along the way:** `@keyframes toast-in` had unitless `bottom: 24; right: 24` (invalid CSS, missing `px`) — the toast likely never actually appeared on screen in any color before this fix.

Wired: oversized-file rejection → warning toast; successful upload → success toast; `Editor.modal.tsx`'s `doUpload` wrapped in try/catch so a failed upload now shows an error toast and leaves the modal open to retry, instead of leaving `isProcessing` stuck `true` with silent failure. Removed two now-redundant ad-hoc hide-timers, one of which had a broken `useEffect` cleanup (`return clearTimeout(...)`, which returns `undefined`, not a cleanup function).

**Verified live**: warning, success, and error toasts all render with correct colors, icons, and messages; the error path correctly keeps the modal open.
