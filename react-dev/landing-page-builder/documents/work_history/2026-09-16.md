## Multi-select property panel + selection borders

**What:** Two related editor bugs — (1) the property panel always showed the generic "Multiple Elements" panel for any multi-selection, even when every selected node was the same content type; (2) non-focused nodes in a multi-selection showed no visual border at all for "content" node types (text/image/button/table/newNode) and Ready Made Templates — only container nodes (section/block/root) had the purple selection outline.

**Why:** User wants same-type selections to expose that type's real controls, and wants every selected node to be visibly marked, not just containers.

**How:**
- `EditorContext.tsx`: refactored `updateNode`/`updateNodeStyle` around a new `getFanOutPaths(targetPath?)` — when no explicit `targetPath` is passed and the current multi-selection (plus focused) all share one content type, the edit applies to every one of those paths instead of just the focused node. Falls back to focused-only otherwise (single selection, or a mixed-type selection), so no existing single-node call site changed behavior.
- `PropertyPanelUI/index.tsx`: computes whether the multi-selection is same-type and, if so, renders that type's own panel (e.g. `TextPanel`) instead of `MultiSelectPanel`; mixed-type selections are unchanged.
- `Contents.tsx` (Text/Image/Button/Table/NewNode) and the shared `readyMadeTemplateShell` in `ReadyMakeTemplates.tsx` (covers all 8 Ready Made Template types via one shell) now check `canvas.selectedNodes` and apply the same `2px solid #a855f7` outline `Container.tsx` already had for layout nodes.

**Caveat found during verification:** the fan-out only reaches controls that call `canvas.updateNode`/`updateNodeStyle`. Text's Typography section (font family/size/color/etc.) drives `canvas.textEditorObj` — tiptap rich-text commands — directly, bypassing both functions entirely, so multi-editing typography on several selected text nodes at once still only affects the focused one. Everything else (size, spacing, background, border, effects, layout) goes through the generic path and does fan out.

**Verified live** (Playwright driving the real dev server, not just `tsc`): selecting 2 sibling text nodes showed "Text Properties" (not "Multiple Elements") and editing the Width field changed both nodes' rendered width (420px → 840px, confirmed via computed style on both); a mixed text+non-text selection still showed the generic panel; selection outlines appeared on non-focused text/image/button nodes and on a Ready Made Template node.

**Result:** All type-checks clean throughout (`npx tsc --noEmit`).
