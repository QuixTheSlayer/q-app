# Session Log — 2026-09-04

Summary of bugs fixed and features added in `react-dev/landing-page-builder` during today's session.

## Drag & drop

**What:** Fixed reorder duplicating the dragged node.

**Why:** `EditorContext.tsx`'s `moveNode` computed the removal parent path with a stray `- 2` offset (`removalPath.lastIndexOf(".") - 2`), which usually pointed at the wrong ancestor. The removal step then filtered that ancestor's children for the dragged node's id, found nothing, and no-opped — so the insert succeeded but the original was never removed.

**How:** Dropped the offset, matching `deleteNode`/`absoluteDeleteNode`'s existing pattern elsewhere in the same file.

## Keyboard shortcuts

**What:** Rebound the theme toggle from `Alt+D` to `Ctrl+Shift+D` (`Cmd+Shift+D` on macOS).

**Why:** Both the theme toggle and prototype-interaction testing were bound to the `Alt` key — holding `Alt` arms "test prototype interaction on click," and the theme toggle was `Alt+D`, so the two conflicted.

**How:** Rebound the theme toggle to `Ctrl+Shift+D`; updated the tooltip/badge and the stale `editor.config.ts` comment (which said `Alt+T` but the code was always `Alt+D`).

## New feature: preview screen size (boxed/max-screen)

**What:** Added a "Preview size" dropdown (Auto / Max screen) to the Page Setting panel with a hover tooltip.

**Decision:** Introduced a new `is_boxed: 1 | 0` field, sibling to `plan_type` on the page record (not inside the CanvasNode tree).

**How:** Added the field to `PageFile`/`PageQueryData` types, threaded it through `getPageData`/`getRenderPageData`, synced it as local state in `Editor.page.tsx`, and passed it down to `Canvas.tsx`. `Preview.page.tsx` and `RenderPage.page.tsx` now apply `main-container` + conditionally `main-container-lp` (existing CSS: `max-width:1200px; margin:0 auto`) based on `is_boxed`.

## BackgroundPicker / Select popover bugs

**What:** Fixed clicking a Select option (Gradient Type, Image Size/Repeat/Position) closing the whole background picker.

**Why:** The shared `Select` component portals its dropdown to `document.body` by default, landing outside the outer react-aria `Popover`'s DOM subtree, so react-aria's dismiss-on-outside-click treated the click as "outside."

**How:** Added a `portalContainer` prop to `Select` and wired `BackgroundPicker`'s own Popover DOM node through to all four nested `Select` instances, so their dropdowns portal *inside* it instead.

**What:** Fixed SketchPicker's color indicator not tracking the live color.

**Why:** `color={localValue}` was stuck at the initial `'#000000'` because `localValue` is only updated when no external `onChange` is supplied, and one always is.

**How:** Reverted to `color={value ?? localValue}`.

**What:** Fixed a regression where every color picker only changed `backgroundColor`, ignoring its actual target.

**Why:** `BackgroundPicker.tsx`'s `onChangeHandler` had been changed to unconditionally call `canvas.updateNodeStyle({backgroundColor: v})`, bypassing the `onChange` prop that all 15+ call sites rely on (Countdown's title/description/footer/basic/primary/secondary colors, `BackgroundColorController`'s animation-effect/URL branching, etc.).

**How:** Restored the `onChange`-respecting behavior, falling back to the direct style update only when no `onChange` is passed.

## Comprehensive Padding / Corner Radius / Box Shadow controllers on Ready Made Templates

**What:** Upgraded the shared `PaddingController` and `BorderRadiusController` (`Sections/relatedComponents/`) to match the Container's actual behavior.

**Why:** These controllers previously diverged from Container's own padding/radius behavior (see `work_history/2026-09-01.md`).

**How:** Switched to em-based values via `CSSUtils`, writes to individual longhand properties (not a combined shorthand string), an "Overall" field, and per-field `PropertyHint` tooltips using the same hint keys Container uses. Since these two components are shared across all 7 template panels, the fix applies uniformly to EventWidgetsGroupTemplate, Cards, Footer, Hero, Layout, NavBar, and PersonalCard panels. Also added the `BoxShadowController` (already existed, used by Container's `StyleSection`) to the same 7 template panels.

## CountDownPanel color bugs

**What:** Fixed a stale closure in "Basic Color."

**Why:** Its `onChange` spread the outer-scope `node` instead of the `prevNode` the updater receives — every other color field correctly used `prevNode`.

**How:** Corrected the closure to use `prevNode`.

**What:** Fixed copy-pasted labels.

**Why:** Description and Footer color pickers were both labeled "Title Color" — missing `descriptionColor`/`footerColor` i18n keys.

**How:** Added the missing i18n keys to en/my/hi.

**What:** Fixed missing content color controllers.

**How:** Moved Title/Description/Footer color pickers out of the "Details" section into "Colors," alongside Basic/Primary/Secondary, so all six live together.

## FaqPanel — missing Card color controller

**What:** Added a "Card color" controller.

**Why:** `FaqVisual.tsx` hardcoded the answer/content card surface to `#ffffff`/`#fff` in several `uiType` variants (Boxed, Two Column, Plus/Minus, Chat Bubble) with no field to customize it.

**How:** Added `cardColor: string` to `FaqNode`, defaulted to `#ffffff`, wired the 5 hardcoded surfaces to `node.cardColor || '#ffffff'`, and added a "Card color" `ColorPicker` row to the panel's Appearance section.

## Thumbnail capture couldn't render background-image (Hero templates)

**What:** Rewrote `convertToCanvas.ts`'s `changeImageUrlFromElement`.

**Why:** It only swapped background-image URLs when hosted on `judgify.me`, and even then injected a badly-sized (`no width/height/object-fit`), unawaited `<img>` behind a fragile `z-index:-1` — background images (which most Hero variants use instead of `<img>` tags) either never got a usable URL or rendered broken.

**How:** Rewrote it to keep the CSS `background-image` (which html2canvas renders natively) and just swap the URL for a fetched/base64 data URL — works for every image host, preserves the template's own `background-size`/`background-position`, and avoids all stacking/timing issues.

## Pricing Toggle — Ribbon variant & height controller

**What:** Fixed ribbon geometry being content-driven.

**Why:** The diagonal ribbon banner's width came from its padding + label text + font size, but its position was a fixed offset — different label lengths shifted the rotated band off the corner or past the card's clip boundary.

**How:** Fixed to a constant `160px` width with `nowrap`/`ellipsis`, independent of label length or font size.

**What:** Fixed the height control having no visible effect on any variant.

**Why:** None of the 8 `uiType` root elements had `h-full`, so even when the outer wrapper (which does receive `node.style.height`) grew or shrank, the inner visual content never stretched/clipped with it.

**How:** Added `h-full` to all 8 variant roots.

## Button (Enterprise) — Corner Badge clipped

**What:** Scoped an `overflow-visible` override for the corner badge.

**Why:** The badge deliberately renders outside the button's own box (`-top-2.5 -right-2.5`), but the shared Ready Made Template shell (`ReadyMakeTemplates.tsx`) applies `overflow-hidden` generically to every template for its hover/focus outline — silently clipping the badge.

**How:** Scoped the `overflow-visible` override to just `contentType === 'buttonEnterprise' && uiType === 'cornerBadge'`, leaving every other template's clip behavior untouched. Confirmed the production/preview render path has no such wrapper, so this was editor-canvas-only.
