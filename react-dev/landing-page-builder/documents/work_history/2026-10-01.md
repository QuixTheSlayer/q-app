## Changes (each behind its own flag in `editor.config.ts`, default `true`)

- **Empty elements stay**: `<span></span>` hamburger bars, bare divs. Imported pages skip the editor's blue empty-block tint.
- `enable_import_code_fences`: a whole AI reply can be pasted; ```css/```js fences become `<style>`/`<script>`.
- Inline styles no longer split on a `;` inside `url(data:...)` or quotes (bug fix).
- `enable_import_all_attributes`: every attribute is kept under its React name, except handlers and a short unsafe list. hidden/inert/popover/disabled/draggable/autoplay apply on the page only. href/target are never passed through, so editor links still don't navigate.
- `enable_import_lossless_text`: TipTap only gets text it gives back unchanged. Classed/styled inline tags, links with an id/class, and small/time/abbr… become their own inline nodes with their own tag. A `<button>` holding tags is a real `<button>` block. A `<blockquote>` with a `<cite>` stays a blockquote.
- `enable_import_raw_elements`: br, canvas, audio, progress, dialog, template… and media with no source are kept as blocks with their real tag. Custom elements keep theirs. Void tags render without children.
- `enable_import_page_scripts`: https `<script src>`, modules and JSON-LD go to `root.pageScripts` and load before the page JS in the sandbox frame and the export.
- `enable_import_html_attributes`: `<html lang class data-theme>` go to `root.htmlAttributes` and onto the sandbox/export `<html>`.

**Not ported:** spaces between two inline siblings (only matters outside flex/grid, which the importer can't tell), `<head>` meta/title, and stylesheets from non-allowlisted hosts.

**Known:** library scripts that look up page classes by their original names (Swiper, Tailwind CDN, Font Awesome) won't find them, because the classes carry the `lp-` prefix.

## Import HTML from the action menu: crash fixed

**Why:** importing HTML into a node from the action menu crashed the page with "Cannot read properties of null (reading 'style')".

**Cause:** `htmlToCanvasNode` (the action-menu path) had returned the pasted HTML string as its `css` since 2026-09-25. ActionMenu merges that into `root.css`, so every character became a class rule (`"0": "<"`...), and the class CSS then hit a null entry.

**Fix:**
- `htmlToCanvasNode` returns class rules, like `htmlToCanvasSections`, and its debug `console.log` is gone.
- `useClassCss` skips entries that aren't rule objects.
- `sanitizeCanvasTree` drops them from a root's `css` on every load (including the array PHP saved), so pages already broken open again.
- New `src/tests/import/htmlToCanvasNode.test.ts`.

## Builder changes for the AI prompt (`codeToNodeTestCodeFiles/prompt.md`)

The user's prompt for AI-generated pages was checked rule by rule against the importer:

- **`enable_editor_page_breakpoints`:** in the editor only, single-width `@media` rules become `@container lp-page` rules in em, and the imported root is that container (`src/utils/editorBreakpoints.ts`). The tablet/mobile views now show the page's own breakpoints at any zoom.
- **`enable_sandbox_forms`:** the sandbox snapshot turns `[data-lp-form]` back into a `<form>`, and a document-level listener cancels navigation after the page's submit handler. JS-handled forms now work in Preview.
- **`enable_editor_open_details`:** imported `<details>` render open in the editor, so FAQ answers can be edited.
- **The prompt itself** (`prompt.md` and the dialog's copy, `importHtmlPrompt.ts`): picsum image URLs, no `<span>`/classes inside text, FAQ via `<details>`, tabs via `hidden`, nothing hidden by CSS on load, scroll-reveal behind `html.js`, a sticky header, one max-width per `@media`, images sized with CSS, and complete class/id literals in JS.

## Lists as blocks, and inline text

- **`enable_import_lists_as_blocks`:** every ul/ol/li is a block with its real tag (never one TipTap list), so items can be added, moved and styled one by one.
- **Text inside an inline-level parent** (span, phrasing tags, label, button, li) is marked `data-lp-inline`, so it keeps the source's line box: the parent font's strut, the marker's line, `li::before` bullets.
- **Imported-page defaults** add `li { list-style: inherit }` (a builder rule set none), nested-list margins with circle/square bullets, and `line-height: normal` on the root unless the page's `*` reset sets one.
- **Imported links and buttons** no longer get the builder's `flex justify-center` classes, so a plain `<a>` in a list item stays inline.
- **Text-tag selectors:** `alsoTargetTextWrappers` also writes a variant with every text-tag compound pointed at its wrapper (`.story p+p`), not just the last.

Checked on a list test page: bullet type, item height and text position match the original in the editor and Preview, for plain, custom-bullet, nested and link lists.

## Button colors on imported pages (test6)

**Why:** changing one button's text color recolored every button on the page.

**Cause:** the editor's class-aware editing (`syncClassStyle`) writes an edit to the node's primary class and to every node sharing it, and all imported buttons share `.btn`.

**Fix:** on imported pages (`isImportedPage`) an edit stays on the edited node. Checked live on test6: without the fix all 4 buttons turned red, with it only the edited one. Buttons recolored before the fix keep their color.
