# 2026-10-30

## Animation effects: timing, easing, presets and visual editors
- Each style effect or preset now has its own `duration`, `delay` and `easing` (presets also `iterations` and `preset`). `useAnimationCss` builds one `transition` per node from those values, limited to the properties each effect changes, instead of a fixed 0.3s.
- New effect types behind `enable_animation_timing`: opacity, scale, translate, skew, blur, text color and 18 presets (entrance and attention). Presets are one frame list in `src/consts/animationEffects.ts`, used for both the CSS `@keyframes` and the motion preview.
- Visual editors (motion + SVG) in `Sections/relatedComponents/animation/`: live effect preview, draggable easing curve with preset chips, a per-trigger timeline (drag a bar for delay, its right edge for duration) and a translate offset pad. Drags write once on release, so one gesture is one undo step. `updateAnimationStyles` was added to `EditorContext` so two style values can be written in one step.
- On View now works for CSS effects: `useScrollToInteractions` sets `data-in-view` at about 15% visible and the generated CSS uses `&[data-in-view]`. Before this the selector was `&:onView`, which is invalid, so those effects never applied.
- Fix: On View entrance presets left the node invisible on the editor canvas (paused on the hidden first frame, no `data-in-view` there). `useAnimationCss(content, { editor: true })` now skips the pause in the editor.
- Blocks that have an animation effect get a dashed outline on the editor canvas (`enable_animation_outline`, zero-specificity `:where()` rule, editor only).
- Property hints added: animationTiming, animationEasing, animationPreset, skew, blur. English strings only.
- Committed as `1488068c7` and `01e1f4f75`.

## Auto save after idle
- The editor saves by itself after `auto_save_delay_ms` (now 3000) with no changes. It only runs while the status is `unsynced`, restarts on every change, does not retry after an error, and skips the plan-tier warning toast. Flag: `enable_auto_save`. Committed in `1488068c7`.

## Icon Block: Iconify icon picker (uncommitted)
- The icon picker in `IconBlockPanel` now lists Iconify icons only. With the search box empty it browses one set at a time (nine sets, a set selector, 48 per page with Load more); typing 2+ letters searches across those sets after a 500 ms pause. The old lucide-react icon list and pager are removed from the picker; lucide names saved earlier still render through `NodeIcon`.
- First version loaded one image per result (48 per search) and Cloudflare rate-limited the developer's IP (error 1015). Reworked: previews come from `/<prefix>.json?icons=...`, one request per set per page, cached for the session and drawn as data-URL images; an HTTP 429 shows a wait message.
- Search follows the Iconify docs: first request `limit=64`; when it comes back full, Load more asks once for everything (`limit=999`) and pages on the client. The API's `total` is only the number returned and `start` does not resume, so neither is used.
- An item's `icon` is an Iconify id (`mdi:home`) or an older lucide name. New `NodeIcon` draws either and replaced the three lucide lookups in `MiscWidgets.tsx` (editor), `Elements.tsx` (production) and the panel header. `isIconifyId` checks every id before it goes into a URL; `toIconifyColor` turns `rgba()` and 8-digit hex into plain hex. The stroke width row is hidden for Iconify icons.
- The `enable_iconify_search` flag was dropped, since there is no other picker to fall back to. Hint `iconSearch` added. Tests: `src/tests/icons/iconify.test.ts` (8 passing). English strings only.
