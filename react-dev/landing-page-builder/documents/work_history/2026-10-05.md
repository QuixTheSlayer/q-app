## Export as a React project (`enable_export_react`)

**What:** Preview has an "Export React" button next to Export. It turns the rendered page into a Vite + React + TypeScript project and downloads it as `<title>-react.zip`: one component per part (navbar, each section, footer), repeated items as one component plus a typed list, the page's JS in `public/scripts` with a runner, the page's CSS in `public/styles`, a README. Modelled on the React export in `frontend-editor` (`D:\Q_P\frontend-editor`, `features/export/react`), ported to `src/utils/reactExport/` (13 files). New dependency: `fflate` (zip). Docs: `documents/code-to-node/08-export-react-project.md`.

**Why from the rendered markup:** it is the same input as Export HTML, so every node type, template and widget is covered by the real renderers with no second set of renderers to keep in step.

**Differences from frontend-editor:** inline styles become React style objects (the builder styles every node inline); `data-id`s are kept only where CSS points at them (otherwise no two cards look alike); the item shape includes the inline style; names come only from `lp-` classes, classes with a rule in the page, or a heading, because builder markup is mostly Tailwind utilities; whitespace helpers ignore the non-breaking space; the app's own versions (React 18.3, Vite 6, TS 5.6); `build` is `vite build` with a separate `typecheck`.

**Verified by measurement** (click the real button in Playwright, unzip, `tsc --noEmit` + `vite build`, serve, compare with Preview): editor-built pages 15, 16, 25, 28, 29 (boxed), 30 (boxed) and imported pages (converted test3, test4, test6 and the exported "Lowe's Has Talent" page, loaded through a Playwright route) all type-check and build, with section heights (or page height against the sandbox frame) equal to Preview and no console errors.

**What the measuring found and fixed:**
- Tables lost the builder's table CSS (441px wide vs 1352px): `BUILDER_CSS` in `projectTemplates.ts`.
- Base font Arial, text rendering and the `calt`/`rlig` settings, the boxed page setting (`is_boxed` -> `main-container-lp`), the builder's rich-text list rules (flattened from CSS nesting) and two global resets from `judgify-react-ui` (`* { padding: 0; margin: 0 }`, `li { list-style: none }`).
- The page's CSS lost ties to Tailwind's reset, because the Tailwind CDN adds its `<style>` after Vite's `<link>`. Fixed by linking the page CSS at the end of `<body>`, from `public/` (Vite would merge a processed stylesheet into `<head>`).
- An imported form is a `<div data-lp-form novalidate>`, which failed `tsc` (React types allow `noValidate` only on `<form>`): attributes a tag does not accept go in `{...({ ... } as object)}`.

**Checked:** 30 new tests (`src/tests/export/reactExport.test.ts`). The typecheck is at the 227 baseline (no errors in the new files; two older errors in `Preview.page.tsx` are not from this).

**Gotchas for whoever continues:** widgets are static (as in Export HTML); the Tailwind CDN script has no integrity hash (dev only, the README says so); `builder.css` copies rules from the builder's stylesheets and does not follow them; only the whole page is exported (frontend-editor can also export one selected part).
