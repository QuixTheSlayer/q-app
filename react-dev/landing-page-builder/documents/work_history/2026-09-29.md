Brought two ideas over from the user's personal app `frontend-editor` (branch `landing-code-to-node`): its DOM → node fidelity rules for Import HTML, and Phase 1 of its property-panel ("inspector") behaviors. Nothing committed yet.

## Import HTML: DOM fidelity

**What:**
- Containers keep their real tag (`node.tag`, allowlist `CONTAINER_TAGS` in `src/utils/nodeAttributes.ts`: nav, ul, li, header, article, figure, label...) and render as it in the editor (`MotionWrapper as`) and production (Root/Section/Block). They carry `data-lp-tag`, which the rich-text `ul`/`ol` rules in `index.css` now skip, so imported menus don't get bullets and padding.
- Safe extra attributes survive (`keptAttributeName`: data-*, aria-*, role, title, lang, dir, rel, tabindex, for), never on* and never the editor's own data-* names. Renderers spread `passthroughAttributes()` before their own props.
- Snippet holders are built in the pasted page's inert document, so nothing loads while converting.

**Tests:** `src/tests/import/domFidelity.test.ts`.

## Property panel Phase 1 (behaviors only, no redesign)

**What** (each behind its own flag in `editor.config.ts`):
- `enable_companion_styles`: `updateNodeStyle` adds the styles that make a change visible. A border width or color also gets `solid`, direction/align/gap also get `display: flex`, and a width lifts a max-width cap (except on root/sections). Keys set in the patch always win. `src/utils/companionStyles.ts`.
- `enable_panel_computed_values`: `usePanelStyle().value(prop)` shows the node's own value, or else what the canvas really renders (imported page CSS included), with the zoom factored out. Padding, margin, gap and corner radius fields use it. `src/hooks/usePanelStyle.ts`.
- `enable_panel_field_reset`: rows that declare `props` on `PanelRowContainer` show a dot and a reset button when the node sets one of them for the current device. Reset removes those values.
- `enable_panel_empty_tips`: four getting-started tips when nothing is selected.
- New keys `panel.fieldChanged`, `panel.resetField`, `panel.tips.*` in all 14 locales.

**Checked:** 228 tests pass (new `src/tests/panel/companionStyles.test.ts`). The typecheck is at the 227 baseline, with no new lint problems. Live check on an imported `.card { padding: 24px; margin: 8px }`: the fields show 24/8 from the CSS. Setting the gap made the block flex/column and showed the dot, and reset cleared it.

**Known:** reset removes only the row's own props, so a companion `display: flex` added by the gap stays.

## Import HTML: full themed pages

**Why:** a full event page (header/main/footer, `:root` variables with a dark-mode variant, Google Fonts, inline SVG dial driven by script, details/summary FAQ, tabbed schedule) imported badly.

**Fixed:**
- **Near-invisible text.** The dark `:root[data-theme="dark"]` values overrode the defaults, so text got `#EFE9E2` on a light background. Inactive root theme variants are now ignored, and a color that only uses `:root` variables stays `var(--ink)`, so dark mode still works.
- **Fonts lost.** A `;` inside the Google Fonts URL cut the `@import` in the sanitizer, `convertCssUnits` and the rule parser. All three now skip quoted strings.
- **The page root lacked the page look.** It now takes the background, color, font and font-size from `body {}`.
- **The FAQ lost its questions, and dl/label CSS stopped matching.** Text-only `summary`, `dt`, `dd`, `label`, `figcaption` and `legend` keep their tag. Empty inline tags such as the `.meter i` bar keep theirs too.
- **Both schedule days showed at once.** `hidden` is kept; the published page applies it and the editor canvas doesn't.
- **The page script died at `#ticks`**, which lives inside an SVG that had become an image, so the countdown, tabs and ticket picker stopped. SVG colors are resolved for the image, and the sandbox snapshot turns marked SVG images back into the live `<svg>`, with scripts and on* handlers stripped.
- Confirmed the section rule: only `<body>`'s direct children (with `<main>` unwrapped) become sections, and everything nested is a block.

**Text colors (follow-up, "most of text color doesn't match").** Measured by rendering the original page and comparing every text node's computed color with the editor and Preview: 54 of 165 differed in the editor and 38 in Preview. There were three causes:
- **Variable clash.** The page's `--muted`/`--bg`/`--surface` clashed with the builder's theme variables; the dark theme's `--muted: 43 54 49` isn't a color. Page variables now get an `--lp-` prefix in the CSS, node styles and JS strings.
- **Page `p` rules on converted text.** Text converted from a `<div class="time">` renders as a TipTap `<p>`, so `.ticket p {}` hit it. That text is marked `data-lp-text="plain"`, and an appended rule makes its `<p>` inherit.
- **Forced black.** The renderers forced `#000000` on text with no class; imported text is now excluded.

Also fixed:
- `form .btn` now points at the form's block (`data-lp-form`).
- Imported links and buttons render as `<a>`/`<button>` in the editor (no href, so no navigation).
- An `h1` holding a span stays a heading, so the hero title keeps its size.

The user chose fidelity ("look exactly as it comes") over keeping the pasted code byte-for-byte. Result: 0 mismatches in both the editor and Preview.

## Sandbox frame: scrolling and in-page links

**Why:** inside the Preview frame the page couldn't scroll, and some JS didn't work.

**Causes and fixes** (`src/utils/security/sandboxDocument.ts`):
- **No scrolling.** The frame copies the app's CSS, which sets `body { overflow: hidden }` for the editor layout. The frame CSS now unlocks html/body scrolling. The snapshot root also loses its own `height`/`overflow` (RenderPage's `<main>` is a 100vh scroll box), so the page scrolls the frame window like a real tab, and window scroll listeners and `scrollY` work.
- **In-page links broke the page.** A srcdoc frame resolves `href="#faq"` against the parent URL, so a click loaded the whole app into the frame. A built-in script now turns `#` links into `window.scrollTo`, honouring scroll-padding-top and leaving the parent page alone. It skips clicks the page handled itself.
- Inline SVGs in the frame go through DOMPurify (`src/utils/inlineSvg.ts`).

**Checked:** in both the Preview and published frames, the wheel scrolls the page, the page's window scroll listener fires, `DOMContentLoaded` runs, and `#faq` lands 72px from the top without moving the parent. The countdown, tabs and dark-mode toggle work, with no errors. 247 tests pass; the typecheck is at the 227 baseline. RenderPage's frame, which the user had commented out, was restored to reproduce the problem.


## Property panel: rotate control for blocks, images and buttons

**What:** a new `RotateSection` (`src/components/PropertyPanelUI/Sections/RotateSection.tsx`) sits after the Style section in the block (Style tab), image and button panels. It hides itself for every other type, including root and sections.
- Controls: a -180° to 180° slider (saved on release, so one drag is one undo step), a degree box, rotate 90° left/right buttons, and the changed dot with reset.
- It writes the CSS `rotate` property, not `transform`, so it adds to the editor's drag and layout transforms instead of fighting them. A 0° value removes the style.
- Writes go through `updateNodeStyle`, so device scope and multi-select apply.
- Images render the node style on both the wrapper and the `<img>` (in the editor and the published renderer). The `<img>` now drops `rotate`, so a picture turns once.
- New keys `controllers.angle`, `rotateLeft90` and `rotateRight90` in all 14 locales. The existing `rotate` hint and "Rotate" label are reused.
- The animation-effect `RotateController` (hover/click effects) is separate and unchanged.
- Gated by `enable_rotate_control` (default `true`, like the other recent panel flags), added afterwards to follow the feature-workflow checklist. The existing `rotate` hint ("Rotates the element around its center", with a turning-square demo) matches this control, so it's reused.

**Checked:**
- 250 tests pass (new `src/tests/panel/rotate.test.ts`; helpers in `src/utils/rotate.utils.ts`). The typecheck is at the 227 baseline, with no lint problems in the new file.
- Live: in the editor, block 20°, button 20° and image +90° all rotate on the canvas, with the dot shown, and text shows no rotate control. In Preview the saved rotations render: block `div` 20°, button `a` 20°, image wrapper 90° with the inner `img` unrotated.
