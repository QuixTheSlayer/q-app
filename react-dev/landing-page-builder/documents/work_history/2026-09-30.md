## What was wrong, and the fix

**Editor rendering** (`NodeMap/Contents.tsx`, `Container.tsx`, `MotionWrapper.tsx`, `css/editor.css`):
- Every text node got the line-clamp setup, whose `overflow: hidden` stopped margins collapsing. Now only collapsable text gets it, and the node style sits on the node element.
- Blocks were forced `position: relative`. Now only root and sections are.
- Images with a picture were forced to flex-centre.
- Every node carried Radix's `type="button"`, which Bootstrap draws as a native button (inline-block spans, dark buttons).
- Builder heading weights hit imported headings.

**Host and builder CSS leaking into the page:**
- Page class names get an `lp-` prefix: `src/utils/pageClasses.ts`, covering CSS, class attributes and JS strings.
- Page ids get an `lp-` prefix too (`nav` becomes `lp-nav`): `src/utils/pageIds.ts`, covering ids, label/aria refs, `#anchor` links, SVG ids, CSS and JS strings. For ids built at runtime, `getElementById` falls back to the `lp-` id (`ID_FALLBACK_SCRIPT`, run before the page JS in the frame, the published page and the HTML export).
- The Preview frame no longer copies Judgify's Bootstrap/Metronic; its `html { font-size: 13px }` shrank every em.
- The page CSS goes last in `<body>`.
- Page rules for tags only (`section { padding }` from the pasted page) had been styling the property panel. They're now limited to the imported root with `:where([data-lp-page])` (`src/utils/pageScope.ts`). That happens at import, and again at render for pages imported earlier.
- Browser defaults for imported pages: headings, lists, dt/dd/label, button colours and `color-scheme: light`. Properties the page's own `*` reset sets are skipped.

**Conversion:**
- **Imported text:** the wrapper now stands for the source element: `data-lp-text="h2"`, the inner TipTap element inherits, and tag rules also target the wrapper. This stopped class font sizes applying twice.
- **Text lists:** the wrapper carries `list-style`, and an item's `<p>` is inline so `li::before` stays on its line. The global rich-text list rules skip imported text.
- **Inline pieces:** loose text next to spans stays inline, with a non-breaking space kept at the edges.
- **Styled inline tags** (`<small>`, `<strong>`, `<time>`) keep their tag. Styled tags inside prose become `<span style>`, with the `font:` shorthand expanded, because TipTap read the weight as a line height.
- **Units:** `clamp()`/`min()`/`max()`/`calc()` font sizes are evaluated. The size in a `font:` shorthand divides by the parent's font size.
- **Buttons:** imported buttons keep the page's font size, and their label has no wrapping `<span>`.
- **New `formField` node** (flag `enable_form_field_import`): `<input>`, `<select>` and `<textarea>` stay real elements, inert in the editor and working in Preview. There's a FormFieldPanel for placeholder, name and options, labels in 14 locales, and the frame snapshot copies each field's live state.
- **SVGs** render as DOMPurify-cleaned inline `<svg>` in the editor and Preview too.

**test3 kitchen timer:**
- The hand ticked around the SVG's corner. Its `class="dial-hand"` inside the SVG kept no prefix while the CSS said `.lp-dial-hand`, so it lost its `transform-origin`/`transition`. SVG classes are now prefixed too (`mapSvgDataUri` in pageClasses.ts, shared with the id renaming).
